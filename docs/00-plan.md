# ボードゲーム得点記録アプリ 計画（v0.1 ドラフト）

作成日: 2026-08-28 / ステータス: **合意待ち**

## 1. 何を作るか

ボードゲームの得点を、その場でスマホに記録するためのアプリ。
サーバーは持たず、データは端末の中だけに保存する。ホーム画面に追加してオフラインでも使える（PWA）。

前提として置いていること（違っていたら指摘してほしい）:

- **1台の端末で記録係が入力する**想定。複数端末でのリアルタイム共有はしない（サーバーレス／ローカル保存という要件から）。
- 記録するのは**プレイヤー × ラウンド の数値**。それ以上のゲーム固有ルール（役の判定、コマの配置など）は扱わない。
- ブラウザのデータを消すとゲーム履歴も消える。バックアップは JSON エクスポートで担保する。

## 2. 要件

| # | 要件 | 対応方針 |
| --- | --- | --- |
| R1 | いろいろなボードゲームで使える | ゲームごとに「得点ルール」を設定（単位・小数・集計方法・勝敗の向き）。プリセットも用意 |
| R2 | 人の登録を最初にする | プレイヤー名簿を端末に永続化。ゲーム作成時は名簿から選ぶだけ |
| R3 | 誰がどういう得点だったかを回ごとに記録 | ラウンド（回）× プレイヤーのマトリクスで保持。途中経過の合計・順位を常時表示 |
| R4 | マイナスも記録できる | 入力は符号付き。± トグルを備えたテンキーで、マイナスが「例外」にならない UI にする |
| R5 | AI っぽくないデザイン | 後述（第5章）。既製 UI キットの初期テーマをそのまま使わない |
| R6 | サーバー不要・ローカルで確認できればよい | 完全クライアントサイド。`npm run dev` で起動 |
| R7 | PWA | manifest + Service Worker でオフライン動作・ホーム画面追加に対応 |

## 3. データモデル

得点の「種類のちがい」は、**値そのものではなく表示と集計のルール**の差でしかない、という整理にする。
値は常に `number`（マイナス・小数OK）で持ち、見せ方と勝敗判定をルール側が決める。

```ts
type Player = {
  id: string
  name: string
  colorKey: string      // 表の識別色（自動割当・変更可）
  createdAt: string
  archived: boolean     // 過去ゲームの整合性を壊さないよう、削除ではなく退避
}

type ScoreRule = {
  unitLabel: string     // "点" / "円" / "勝" / "VP" など
  prefix: string        // "¥" など（無しも可）
  decimals: 0 | 1 | 2
  step: number          // テンキーの増減単位（1 / 10 / 100 / 1000）
  initialScore: number  // 開始時の持ち点。0 以外にすると減点式になる（合計のときだけ効く）
  roundSum: number|null // 1回ぶんの合計がいくつになるはずか。null なら確認しない
  mahjong: {            // 麻雀のポイント計算。null なら入れた点をそのまま使う
    startScore: number  //   配給原点（既定 30000）
    returnScore: number //   返し点（既定 30000＝オカなし）。オカ＝（返し点−配給原点）×人数÷1000 を1位に
    uma: number[]       //   順位ウマ。例 [20, 10, -10, -20]
    input: 'points'|'raw' //  何を入力するか。ゲーム画面で切り替えられる
  } | null              //   入力はウマ・オカを足す前のポイント。表には最終ポイントとカッコ書きで両方出す
  quickValues: number[] // ワンタップ入力用（最大6つ。既定は [-3, -2, -1, 1, 2, 3]）
  aggregation: 'sum' | 'average' | 'max' | 'last'  // 総合点の出し方
  direction: 'highest' | 'lowest'                  // 高い方が勝ち / 低い方が勝ち（失点式）
}

type Game = {
  id: string
  name: string          // "カタン 2026-08-28" など
  rule: ScoreRule       // 作成時にコピーして埋め込む（プリセット変更の影響を受けない）
  playerIds: string[]
  createdAt: string
  finishedAt: string | null
  memo: string
}

type Round = {
  id: string
  gameId: string
  index: number         // 1始まり
  label: string         // 空なら "第N回"
  scores: Record<PlayerId, number | null>  // null = 未入力（0 と区別する）
}
```

プリセット（初期値。ゲーム作成時に選んで、その場で微調整できる）:

| プリセット | 単位 | 集計 | 勝敗 | 備考 |
| --- | --- | --- | --- | --- |
| 合計が多い人が勝ち | 点 | 合計 | 高い方 | 既定 |
| 合計が少ない人が勝ち | 点 | 合計 | **低い方** | ワンタップ値は上と同じ |
| 麻雀 | pt | 合計 | 高い方 | ウマ・オカ前のポイントを入れ、最終ポイントと並べて出す。4人必須 |

プリセットは当初6種（金額・勝利数・麻雀素点を含む）用意したが、2026-08-28 に上記2種へ絞った。
数えるものが違うゲームは、作成画面の「詳細を編集」で単位・小数桁・集計方法を変えれば作れるため、
選択肢が多いほうが選びにくいという判断。

保存先: **localStorage に単一 JSON**（`bgs:v1`）。データ量は多くても数十KBで、IndexedDB を持ち出すほどではない。
書き込みは「更新のたびに全体を保存」で足りる。スキーマに `version` を持たせ、将来の移行に備える。

## 4. 画面

| 画面 | 中身 |
| --- | --- |
| ホーム | 進行中のゲーム（あれば大きく）／履歴一覧／新規作成ボタン |
| プレイヤー名簿 | 追加・改名・並べ替え・退避。ここを最初に通す導線にする |
| ゲーム作成 | 名前 → プリセット選択 → ルール微調整 → 参加者を選ぶ（3ステップ） |
| **スコアボード**（主画面） | 行=ラウンド、列=プレイヤーの表。上部に現在の合計と順位を固定表示。セルをタップで入力シート |
| 入力シート | 大きなテンキー、± トグル、quickValues のワンタップ、「次のプレイヤーへ」で連続入力 |
| 結果 | ゲーム終了時の最終順位。メモを添えて履歴に残す |
| データ管理 | JSON エクスポート／インポート／全消去 |

入力の作りで重視する点:

- プレイヤーが5人を超えると横に収まらないので、**表は横スクロール、プレイヤー名の列は固定**。
- ラウンド追加は1タップ。1ラウンド分を**全員まとめて入力**する流れを既定にする（1人ずつより速い）。
- 未入力（null）と 0 を見た目で区別する。
- 直前の操作の取り消し（1段階の undo）を用意する。誤タップの復旧が一番効く場所なので。

## 5. デザイン方針

「AI っぽい」＝避けるもの:
紫〜青のグラデーション、ガラスモーフィズム、過剰な角丸、絵文字アイコン、ふわっとした影の多用、
どこかで見た SaaS 風カードの羅列、Inter そのまま。

**3案を全部作り、設定で切り替えられるようにする**（2026-08-28 決定）。既定は「紙」。

| テーマ | 中身 |
| --- | --- |
| 紙（paper・既定） | 生成りの紙地に細い罫線。影を使わず、線と余白で構造を作る。数字は等幅・タビュラー |
| レトロ（retro） | 太い罫・角ゼロ・朱／紺／黄。硬いオフセット影で「押せる物体」の感じを出す |
| ミニマル（swiss） | 白黒＋朱1色。グリッドと余白だけで階層を作り、数字を主役にする |

全テーマ共通で守ること:

- プラス/マイナスは色に頼らず、記号（−）と桁揃えでも判別できるようにする。
- タップ領域は 44px 以上。入力は下から出るボトムシート。
- アイコンは最小限。ラベルは日本語の言葉で書く。

### テーマの実装方法

`mockups/themed.html` で実際に動かして確認済み。**HTML は 1 種類**のまま、次の3層で差を吸収する。

1. **トークン**（`[data-theme="..."]` に定義する CSS 変数）: 色・フォント・罫の太さ・角丸・影。差の大半はここで済む。
2. **テーマ固有の上書き**: 構造が変わる部分だけ（例: レトロは順位を2列カードにする、ミニマルは色面を全部やめる）。
3. **ラベルの出し分け**: `1位 / 1ST / 01` のような表記差は、要素に `data-ja` `data-en` `data-num` を持たせて
   `content: attr(...)` で出す。DOM を分岐させない。

選択はアプリ全体の設定として `localStorage` に保存する（ゲームごとではない）。切り替えは即時反映。

**コスト**: 画面や部品を1つ作るたび、3テーマでの見え方を確認する手間が増える。
これを抑えるため、**マークアップは常にテーマ非依存に保つ**（見た目の都合で DOM を足さない）ことを規律にする。
新しい色や寸法が要るときは、その場でハードコードせず必ずトークンを増やす。

## 6. 技術構成

| 項目 | 採用 | 理由 |
| --- | --- | --- |
| ビルド | Vite + TypeScript | 静的ファイル出力だけで完結し、PWA プラグインも揃っている |
| UI | React | ラウンド×プレイヤーの状態更新が主で、宣言的に書けると素直 |
| ルーティング | react-router | 画面数が7つ程度。履歴の戻るがスマホで効くのは重要 |
| 状態 | React 標準（Context + reducer）+ localStorage 同期 | サーバー通信が無く、データ取得ライブラリは不要 |
| スタイル | CSS Modules + CSS Variables | 第5章の通り |
| PWA | vite-plugin-pwa | manifest 生成・Service Worker・更新通知まで込み |
| Lint | oxlint | 高速で設定が軽い |

ライブラリは一律で最新安定版を使う。型エラー等で維持できない場合は、勝手に下げずに相談する。

確認方法:

- 開発中: `npm run dev` （Service Worker は無効。UI の確認はこちら）
- PWA の確認: `npm run build && npm run preview` （localhost なら SW が動く）
- **スマホ実機**: `--host` で LAN 公開しても、PWA は https でないとインストールできない。
  mkcert で自己署名 https を立てるか、Cloudflare Quick Tunnel で一時 URL を作って実機ブラウザで開く。
  どちらにするかは実機確認のフェーズで決める。

## 7. 決まったこと・未決

決定済み（2026-08-28）:

- **UI は自作 CSS**（CSS Modules + CSS Variables）で組む。MUI は入れない。
- **複数端末での共有は不要**。1台の端末で記録係が入力する前提で進める。
- **デザインは3案とも作り、設定で切り替えられるようにする**。既定は「紙」。

未決（実装しながら決めればよいもの）:

- テーマごとにアプリアイコン（PWA の manifest）を変えるかどうか。ホーム画面のアイコンは
  インストール時に固定されるため、切り替えても追従しない。既定テーマの1種類で作るのが素直。
- プレイヤーの識別色を「ミニマル」でどう扱うか（現状は非表示。名前だけで足りるか実機で確認する）。

### 実装中に見つけて直したこと

- `new Date().toISOString().slice(0,10)` は UTC の日付になるため、日本時間の夜に作ると日付が1日ずれる。
  `src/lib/date.ts` にローカル日付のヘルパーを作って置き換えた。
- レトロ／ミニマルに切り替えたとき、色面の上の文字が同色になって消える箇所があった
  （紺地に紺の列名など）。`--head-ink-mute` トークンを足して解消。テーマを増やすときは
  「色面の上に載る文字」を必ず実画面で確認する必要がある。

- **2026-08-28 公開**。GitHub にリポジトリを作り（公開設定。無料プランの Pages は公開リポジトリが必要）、
  GitHub Actions から Pages に配信した。**https://esystimsesys.github.io/boardgame-scorer/**
  - プロジェクトページはサブディレクトリ配信になるため、`vite` の `base`、`BrowserRouter` の `basename`、
    PWA の `start_url` / `scope` / `navigateFallback` をすべて `/boardgame-scorer/` に合わせた。
  - 実機の代わりに、公開後の URL に対して Service Worker の登録・manifest・直リンク（`/players`）の
    描画までヘッドレスブラウザで確認済み。**スマホ実機でのインストール確認だけが残っている**
    （公開 URL は https なので、この URL をスマホで開けばそのまま確認できる）。
